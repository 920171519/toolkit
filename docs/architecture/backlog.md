# 架构优化任务池

| 优先级 | 任务 | 已核对的重复、偏离或约束 | 迁移和验收 |
| --- | --- | --- | --- |
| 进行中 | 全量架构验收 | 流程与设置的读写入口完成主要迁移，历史兼容仍需按契约核对。 | 检查活动入口、依赖、重复规则、数据兼容和回归证据，明确可实施及仍需确认的事项。 |
| 进行中 | 单独修复首次切换 WAL 时的锁竞争 | Linux 与 Windows 上另一个连接持有写锁时，设置 WAL 可立即返回 SQLITE_BUSY。启动迁移和演示数据事务尚未开始。 | 在相同等待上限内单独处理 WAL 初始化，验证正在释放的锁、超时、其他 SQLite 错误与旧数据保留。 |
| 进行中 | 表头弹窗持有筛选和分页参数状态 | 渲染多个筛选表头时，各自传输从现有参数推导的状态。 | 验证菜单、表单、清空、项目范围、分页命名及返回，核对页面响应实际减少的字段。 |
| 进行中 | 统一责任田分工事实的读取来源 | 转测授权及组织目录分别从三个相同分工表读取用户与责任田。 | 保留专用查询、归档分工、历史回退及事务内授权校验。 |
| 待确认 | 多个集成测试责任田的授权 | 结论提交使用排序第一的集成测试责任田，部分读权限和选人范围使用所有标记为集成测试的责任田。当前设置界面不写该标记，历史库仍可能有多个。 | 核实实际部署配置并确认多个责任田时的办理规则，再统一读写权限。 |
| 待确认 | 集成测试进展可记录的阶段 | 批次详情仅在测试中显示记录入口，写入权限通过后未校验批次状态。业务说明同时记录了测试中可提交和可随时提交。 | 确认草稿及历史批次是否应追加进展，再同步入口、写入校验和操作指南。 |
| 待确认 | 核查历史跨项目批次关联 | 现行写入校验申请和批次同项目，兼容的读取按批次实际所属项目授权。历史记录保留原有关联。 | 有生产核查授权后，确认历史数据范围和业务含义，再决定是否需要修复记录。 |
| 待确认 | 核查历史审批人快照 | 旧启动迁移可能将当前节点审批人加入已发试制的快照。现存快照缺少可区分增补来源的标记。 | 取得生产核查授权后，用可信的发布记录与审批分工核对，确认是否调整历史数据。 |
| 待确认 | 确认部署环境如何声明已停服 | 部署脚本已修复匹配和停启单元名。无匹配服务且没有停止命令时仍提示由外部停服，随后进入安装和构建。 | 核实非 systemd 环境如何接管停启，确认缺少停止方式时应否中止或要求显式声明。 |
| 待确认 | 收缩历史模型和字段 | `binding_tasks`、`risk_reviews`、`formal_reviews` 仍参与历史范围、删除保护或详情 JSON。旧项目经理字段见既有数据迁移。 | 先核实生产库与外部调用方使用情况。需要移除字段、数据或权限时另立迁移方案，与用户确认。 |

治理按可验证的行为批次推进。新逻辑完成覆盖和迁移后删除被替代的实现。每批验证后独立提交。
