# 架构优化任务池

| 优先级 | 任务 | 已核对的重复、偏离或约束 | 迁移和验收 |
| --- | --- | --- | --- |
| 待确认 | 多个集成测试责任田的授权 | 结论提交使用排序第一的集成测试责任田，部分读权限和选人范围使用所有标记为集成测试的责任田。演示库只有一个，表结构允许多个。 | 核实实际部署配置并确认多个责任田时的办理规则，再统一读写权限。 |
| 中 | 收拢剩余 Action 和路由的数据库访问 | 注册和登录已通过认证服务。工作流 Action 仍直查批次编号和试制记录，通知已读接口仍直接写 SQLite。 | 分别核对写入与重试约定，把数据库访问移到明确的记录所有者，并扩展入口约束。 |
| 中 | 治理独立验证门槛 | 当前主要靠本地 ESLint、构建、类型检查和 Playwright。基线无仓库 CI 配置。 | 本机稳定后选必要的快速检查和完整回归策略。涉及外部 CI 成本、权限或发布条件时先确认。 |
| 待确认 | 收缩历史模型和字段 | `binding_tasks`、`risk_reviews`、`formal_reviews` 仍参与历史范围、删除保护或详情 JSON。旧项目经理字段见既有数据迁移。 | 先核实生产库与外部调用方使用情况。需要移除字段、数据或权限时另立迁移方案，与用户确认。 |

治理按可验证的行为批次推进。新逻辑完成覆盖和迁移后删除被替代的实现。每批验证后独立提交。
