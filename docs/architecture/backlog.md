# 架构优化任务池

| 优先级 | 任务 | 已核对的重复、偏离或约束 | 迁移和验收 |
| --- | --- | --- | --- |
| 中 | 完成测试环境跨平台验证 | 原生命令已在 Windows 实跑。WSL 当前缺少满足最低版本的 Node 和 Chromium。测试运行数据留在系统临时目录。 | 在支持版本的 Linux 上复验相同命令。核对测试数据保留和并行端口说明，评估合适的临时数据清理时机。 |
| 待确认 | 多个集成测试责任田的授权 | 结论提交使用排序第一的集成测试责任田，部分读权限和选人范围使用所有标记为集成测试的责任田。演示库只有一个，表结构允许多个。 | 核实实际部署配置并确认多个责任田时的办理规则，再统一读写权限。 |
| 中 | 统一列表分页控件 | 原生弹窗生命周期已统一。设置目录、设置列表和流程列表仍有不同的分页控件。 | 收拢同义的交互和样式，保留提交方式、键盘、窄屏和无 JS 路径。 |
| 中 | 整理 URL 模型和工具函数 | `directoryHref` 与 `workflowHref` 对空参数处理不同。`proxy.ts` 和 `lib/return-to.ts` 都列出工作区路由，框架需要字面量匹配器。 | 固定深链和返回参数的行为。为代理匹配器和工作区范围加一致性检查，再收拢已确认同义的 URL 处理。 |
| 中 | 汇总运行配置和操作错误 | 审计写入已统一。数据库路径在应用和重置脚本中分别解析，会话、演示数据及部署参数分布在多个入口。 | 核对默认值、配置优先级和错误提示，保留现有命令、部署参数及事务回滚。 |
| 中 | 治理独立验证门槛 | 当前主要靠本地 ESLint、构建、类型检查和 Playwright。基线无仓库 CI 配置。 | 本机稳定后选必要的快速检查和完整回归策略。涉及外部 CI 成本、权限或发布条件时先确认。 |
| 待确认 | 收缩历史模型和字段 | `binding_tasks`、`risk_reviews`、`formal_reviews` 仍参与历史范围、删除保护或详情 JSON。旧项目经理字段见既有数据迁移。 | 先核实生产库与外部调用方使用情况。需要移除字段、数据或权限时另立迁移方案，与用户确认。 |

治理按可验证的行为批次推进。新逻辑完成覆盖和迁移后删除被替代的实现。每批验证后独立提交。
