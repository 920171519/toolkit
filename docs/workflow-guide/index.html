01待转测申请

提交软件包版本

软件包所属责任田人员或管理员

待转测申请 → 提交转测申请

开始前
软件包已启用，且至少关联一个在行项目节点。准备版本号、变更说明、归档和构建链接。
完成后
各在行使用项目的「待安排申请」出现同一版本。到对应项目勾选本轮转测。

该包须已启用并关联至少一个在行项目节点。变更说明至少 5 个字符，归档和构建地址使用 HTTP(S)，同一包的版本号不能重复。

勾选本轮配套并发起转测

本项目软件经理或管理员

待转测申请 → 待安排申请 → 准备转测批次

开始前
切到要测试的项目。至少有一份待转测申请，并勾选目标版本纳入本轮。共享包在每个项目分别处理。
完成后
保存草稿后还要点「发起转测」。从「集成测试 → 在测批次」按批次号打开。

批次号以 B 开头，后接至少 3 位数字，且全局唯一。每批至少选一份待转测申请，同包只选一个版本。筛选隐藏的已勾选项仍计入本轮。暂缓的申请留给下一轮。

下一步提交申请会为所有在行使用项目生成一份转测申请。每个项目发起自己的批次，集成测试负责人在「在测批次」接手。

02集成测试

验证配套并提交结论

集成测试责任田主管、本项目测试负责人或管理员

集成测试 → 在测批次 → 处理测试批次

开始前
批次已发起，配套快照显示目标版本纳入本轮。验证完成后准备测试总结和报告。
完成后
批次进入「历史批次」。核对软件包全部在行使用项目的结论，全部通过后在「待发布试制」找同一版本。

测试总结至少 10 个字符，报告不超过 15 MB。选「测试不通过」时填写问题归属。软件经理可点「查看批次进展」，结束后从「历史批次」查阅结论和报告。

下一步单项目包通过即进待发布试制。共享包要等全部在行使用项目通过。图中的 1002CFG 同时用于星云 N1 和磐石 T3，N1 批次通过后还需为 T3 发起转测并通过。

03试制与绑定验证

发布共享试制

任一在行使用项目的软件经理或管理员

试制与绑定验证 → 待发布试制

开始前
普通试制要求该版本在全部在行使用项目通过。已登记原因的风险试制会走同一个队列。准备试制电子流和评审纪要。
完成后
确认发布后，各在行使用项目进入同一次共享试制。到「节点绑定」决定绑定方式。

填写试制电子流的 HTTP(S) 网址和试制评审纪要。一个软件包版本发布一次，各在行使用项目同步。

决定绑定方式

当前项目的软件经理或管理员

试制与绑定验证 → 节点绑定 → 决定绑定方式

开始前
版本已发布试制，绑定方式待决定。需要实机验证时，核对各项目应验证的节点。
完成后
推送后按节点提交电子流。确实整版无需绑定时，填写免绑原因，等已安排的测试结束后到「转正发布」。

推送后各项目节点收到绑定待办。整版免绑在推送前登记。推送后如只有个别节点无需绑定，本项目软件经理、管理员或该节点绑定责任人可点「节点无需绑定」并填写原因。

提交设备条码和电子流

节点绑定责任人、绑定验证员或管理员

我的工作台 → 绑定待办，或 节点绑定 → 查看节点与审批

开始前
已推送绑定任务，节点仍开放绑定。找到对应项目、版本和节点，备齐设备条码与网页电子流地址。
完成后
电子流显示「待审批」。由所选审批人或有权管理员进入该条记录审批。

设备条码可逐行录入，网页电子流用 HTTP(S) 网址。版本转正前，条码达标后仍可补交电子流。

审批绑定电子流

指定电子流审批人或管理员

我的工作台 → 审批绑定电子流，或 绑定详情 → 对应电子流

开始前
电子流为「待审批」。打开电子流核对条码并填写审批意见，提交人不能自审。
完成后
审批通过的有效条码计入节点。条码达标后由有确认权限的人点「确认节点通过」。

提交人不能审批自己提交的电子流。审批通过会累计有效条码，节点还需确认。

核对验证结果并确认节点通过

软件包当前责任人、该节点所属项目的软件经理或管理员

我的工作台 → 确认节点通过，或 绑定详情 → 对应节点

开始前
该节点已推送、尚待确认。审批通过的有效条码达到该节点要求。
完成后
该节点标为「绑定通过」。所有在行使用项目节点通过或登记免绑，且已安排的测试结束后，到左侧「转正发布」。

已审批条码达到门槛后，核对验证结果并确认节点通过。仍部署仓库版本 5944e50 的站点使用此前规则，由该任务指定的绑定责任人确认。

下一步所有在行项目的节点确认通过或登记免绑，且已安排的集成测试结束后，版本自动移到「转正发布」。

1006KEY 1.3.0 已超期，为什么还不能转正？

初始演示数据的试制期限是 3 天。星云 N1 只完成 EVT，PVT 还有一条电子流待审批。极光 M2 和磐石 T3 的 EVT、PVT 还要提交条码和电子流。逐节点审批、确认后，在绑定详情点「前往转正发布」，再从转正核对页发布。

需要提前试制

本项目软件经理或管理员在待转测申请、在测批次或未通过记录中登记风险原因，再从试制队列发布。已安排的测试继续，结束前无法转正。测试确认软件包相关问题时，提交结论会作废勾选的风险试制版本，相关绑定电子流需要撤销。

04转正发布

核对各项目证据，发布正式版本

任一在行使用项目的软件经理或管理员

转正发布 → 核对并转正

开始前
版本已进入待转正队列，各在行项目的已安排测试均结束、节点已确认通过或免绑。发布前处理完待审批的绑定电子流。
完成后
确认发布后，在「版本全链路」看到「正式版本」及转正电子流，也可回「软件版本总览」核对正式版本号。

通用发布截图用已满足条件的 1004NET 演示。跟做 1006KEY 时在待转正列表找 1006KEY 1.3.0。待审批电子流可从「查看绑定验证记录」进入处理。

发布结果一个版本发布一次，所有在行使用项目同步成为正式版本。结果可从软件版本总览和版本全链路查看。

卡在某一步时

测试通过了，怎么没有进入待发布试制？

先在批次配套快照确认该版本已纳入本轮转测，再从「软件版本总览」核对它的在行使用范围。看到「待其他项目验收」时检查其他项目的最新结论。看到「待补转测申请」时核对各项目申请记录和使用范围。各项目均通过后，进入该版本的使用项目，并检查试制队列的搜索和表头筛选。

绑定通过后，怎么又回到节点绑定？

新增审批通过或撤销已通过的电子流后，需重新确认受影响的节点。撤销入口在绑定详情的电子流记录中，提交人、本项目软件经理或管理员可以填写原因后撤销待审批或已通过的电子流。

已有待转正版本，怎么没有发布按钮？

核对页会提示还有多少条绑定电子流待审批。先处理审批或撤销。发布按钮给在行使用项目的软件经理和管理员使用。

显示已超期，还能转正吗？

可以。超期提示用于催办。待转正版本仍可点「核对并转正」。版本若还在节点绑定页，先核对所有在行节点是否已确认或免绑、已安排的集成测试是否结束，以及绑定电子流的审批状态。

项目 PM 要在哪里操作？

PM 可查阅项目基础信息和联系人。发起转测、确认节点、转正发布按项目软件经理、节点确认人等对应权限开放。
