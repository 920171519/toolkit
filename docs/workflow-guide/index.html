01待转测申请

提交软件包版本

软件包所属责任田人员或管理员

待转测申请 → 提交转测申请

该包须已启用并关联至少一个在行项目节点。变更说明至少 5 个字符，归档和构建地址使用 HTTP(S)，同一包的版本号不能重复。

勾选本轮配套并发起转测

本项目软件经理或管理员

待转测申请 → 待安排申请 → 准备转测批次

批次号以 B 开头，后接至少 3 位数字，且全局唯一。每批至少选一份待转测申请，同包只选一个版本。筛选隐藏的已勾选项仍计入本轮。暂缓的申请留给下一轮。

下一步提交申请会为所有在行使用项目生成一份转测申请。每个项目发起自己的批次，集成测试负责人在「在测批次」接手。

02集成测试

验证配套并提交结论

集成测试责任田主管、本项目测试负责人或管理员

集成测试 → 在测批次 → 处理测试批次

测试总结至少 10 个字符，报告不超过 15 MB。选「测试不通过」时填写问题归属。软件经理可点「查看批次进展」，结束后从「历史批次」查阅结论和报告。

下一步单项目包通过即进待发布试制。共享包要等最后一个在行使用项目通过，再进入普通试制队列。

03试制与绑定验证

发布共享试制

任一在行使用项目的软件经理或管理员

试制与绑定验证 → 待发布试制

填写试制电子流的 HTTP(S) 网址和试制评审纪要。一个软件包版本发布一次，各在行使用项目同步。

决定绑定方式

当前项目的软件经理或管理员

试制与绑定验证 → 节点绑定 → 决定绑定方式

推送后各项目节点收到绑定待办。整版免绑在推送前登记。推送后如只有个别节点无需绑定，本项目软件经理、管理员或该节点绑定责任人可点「节点无需绑定」并填写原因。

提交设备条码和电子流

节点绑定责任人、绑定验证员或管理员

我的工作台 → 绑定待办，或 节点绑定 → 查看节点与审批

设备条码可逐行录入，网页电子流用 HTTP(S) 网址。版本转正前，条码达标后仍可补交电子流。

审批绑定电子流

指定电子流审批人或管理员

我的工作台 → 审批绑定电子流，或 绑定详情 → 对应电子流

提交人不能审批自己提交的电子流。审批通过会累计有效条码，节点还需确认。

核对验证结果并确认节点通过

按部署版本确定节点确认人

我的工作台 → 确认节点通过，或 绑定详情 → 对应节点

基于仓库版本 5944e50 的部署，由该任务指定的节点绑定责任人确认。采用权限调整版的部署，由软件包当前责任人、该节点所属项目的软件经理或管理员确认。已审批条码达到门槛才可确认。

下一步所有在行项目的节点确认通过或登记免绑，且已安排的集成测试结束后，版本自动移到「转正发布」。

需要提前试制

本项目软件经理或管理员在待转测申请、在测批次或未通过记录中登记风险原因，再从试制队列发布。已安排的测试继续，结束前无法转正。测试确认软件包相关问题时，提交结论会作废勾选的风险试制版本，相关绑定电子流需要撤销。

04转正发布

核对各项目证据，发布正式版本

任一在行使用项目的软件经理或管理员

转正发布 → 核对并转正

核对各项目验收、节点确认和电子流。待审批电子流可从「查看绑定验证记录」进入处理。转正电子流使用 HTTP(S) 网址。

发布结果一个版本发布一次，所有在行使用项目同步成为正式版本。结果可从软件版本总览和版本全链路查看。

卡在某一步时

测试通过了，怎么没有进入待发布试制？

从「软件版本总览」核对在行使用范围。看到「待其他项目验收」时检查其他项目的最新结论。看到「待补转测申请」时核对各项目申请记录和软件包使用范围。

绑定通过后，怎么又回到节点绑定？

新增审批通过或撤销已通过的电子流后，需重新确认受影响的节点。撤销入口在绑定详情的电子流记录中，提交人、本项目软件经理或管理员可以填写原因后撤销待审批或已通过的电子流。

已有待转正版本，怎么没有发布按钮？

核对页会提示还有多少条绑定电子流待审批。先处理审批或撤销。发布按钮给在行使用项目的软件经理和管理员使用。

项目 PM 要在哪里操作？

PM 可查阅项目基础信息和联系人。发起转测、确认节点、转正发布按项目软件经理、节点确认人等对应权限开放。
