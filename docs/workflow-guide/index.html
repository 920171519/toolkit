01待转测申请

项目工作区 → 待转测申请 → 待安排申请 / 待发起批次

  1. 软件包所属责任田人员
    或管理员

    点 提交转测申请，选择软件包，填写版本号、变更说明、包归档链接和构建地址，再点 提交申请。

    责任田主管、项目负责人或成员按所属责任田申请。软件包需启用并关联至少一个在行项目节点。版本号不能重复，变更说明至少 5 个字符，两个链接均使用 HTTP(S)。

  2. 本项目软件经理
    或管理员

    在「待安排申请」勾选本轮要测的版本，点 准备转测批次。填批次号，核对完整配套，再点 保存草稿并核对。

    批次号以 B 开头，后接至少 3 位数字，且全局唯一。每批至少选一份待转测申请，同包只选一个版本。筛选隐藏的已勾选项仍计入本轮。

  3. 本项目软件经理
    或管理员

    核对批次草稿后点 发起转测。稍后继续时，从「待发起批次」点 核对并发起。

交接 提交版本会为所有在行使用项目生成转测申请。发起批次后，项目的集成测试负责人接手，暂缓的申请留待下一轮。

02集成测试

项目工作区 → 集成测试 → 在测批次

  1. 集成测试责任田主管、本项目负责人或管理员

    点 处理测试批次，按批次中的软件包和版本做验证。测试过程中可用 记录进展 留下阶段结果。

  2. 集成测试责任田主管、本项目负责人或管理员

    点 提交测试结论，选择「测试通过」「测试不通过」或「无法完成验证」。填写测试总结、上传验证报告，再点 提交验证结论。选「测试不通过」时填写问题归属。

    总结至少 10 个字符，报告不超过 15 MB。软件经理可点「查看批次进展」。完成后的批次和报告可在「历史批次」查阅。

交接 单项目包通过后自动进入「待发布试制」。共享包等最后一个在行使用项目通过，再进入普通试制队列。

03试制与绑定验证

项目工作区 → 试制与绑定验证 → 待发布试制 / 节点绑定

  1. 在行使用项目的软件经理或管理员

    在「待发布试制」点 发布，核对验收依据，填写试制电子流网址（HTTP(S)）和试制评审纪要，再点击 发布全项目共享试制版本 并确认。

    同一软件包版本发布一次，各在行使用项目同步进入试制。

  2. 该项目软件经理
    或管理员

    切换到「节点绑定」，点 决定绑定方式，再点 推送绑定任务。需要免绑时，按下方对应场景登记。

  3. 节点绑定责任人、绑定验证员或管理员

    在绑定详情展开节点，点 新增绑定电子流，选审批人，录入设备条码和网页电子流地址，再点 提交绑定电子流。条码可逐行录入。

  4. 指定电子流审批人
    或管理员

    点 审批电子流，核对条码和电子流，填写审批意见，再点 审批通过 或 审批驳回。提交人不能审批自己提交的电子流。

  5. 节点确认人
    按部署版本

    已审批条码达到节点要求后，核对验证结果，点击 确认节点通过。系统记录确认人和时间。

    在仓库版本 5944e50中，由试制发布时指定的节点绑定责任人确认。这个人可从工作台打开确认待办。

    在已采用确认权限调整的版本中，由软件包当前责任人、该节点所属项目的软件经理或管理员确认。绑定责任人负责提交条码和电子流。

交接 全部在行项目的节点确认通过或登记免绑，且已安排的集成测试结束后，版本自动进入「转正发布」。

整版或单节点无需绑定

整版免绑由软件经理或管理员在推送前选择「无需绑定」并填写原因。推送后若仅个别节点无需绑定，本项目软件经理、管理员或该节点的绑定责任人可点「节点无需绑定」，填写该节点的免绑原因。

需要提前试制

本项目软件经理或管理员可在待转测申请、在测批次或测试未通过的记录中「登记风险原因」，再从试制队列发布。已安排的测试继续进行，未结束前无法转正。

风险试制期间，如果测试不通过且确认是软件包问题，提交结论会作废其中勾选的风险试制版本。相关绑定电子流需要撤销。

04转正发布

项目工作区 → 转正发布 → 核对并转正

  1. 在行使用项目的软件经理或管理员

    找到待转正版本，点 核对并转正，核对各项目验收、节点确认、免绑和电子流。需要回查时点 查看绑定验证记录。待审批的绑定电子流须先处理。

  2. 在行使用项目的软件经理或管理员

    点 发布正式版本，填写转正电子流网址（HTTP(S)）和转正评审纪要，再点 提交转正电子流并发布。

结果 发布一次，所有在行使用项目同步使用该正式版本。可从「软件版本总览」或「版本全链路」查阅结果。

卡在某一步时

本项目测试通过了，版本还没进待发布试制

在「软件版本总览」查看软件包的在行使用范围。显示「待其他项目验收」时，查看其他使用项目的最新批次结论。显示「待补转测申请」时，联系配置人员核对软件包使用范围和各项目的转测记录。

条码达标了，节点为什么还是待确认？

电子流审批与节点确认是两步。按「试制与绑定验证」一节的版本说明，由有权确认的人在绑定详情完成确认。新增审批通过的电子流，或撤销已通过的电子流后，受影响的节点需要重新确认。

版本已待转正，为什么没有发布按钮？

先查看转正核对页有无待审批电子流提示。有待审批项时，从「查看绑定验证记录」处理审批或撤销。发布权限由在行使用项目的软件经理和管理员持有。
